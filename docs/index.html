> odm

Oryn Download Manager. A CLI download manager that takes one connection budget and splits it sensibly — across files, across engines, across mirrors. Work-stealing chunks, resume with per-chunk SHA-256, a JSON-RPC daemon for GUIs. Inspired by aria2c. Written in Go.

$ paru -S odm-bin
$ yay -S odm-bin
$ git clone https://github.com/Fahry-a/ODM && cd ODM && go build -o odm ./cmd/odm

Prebuilt on the AUR for i686, x86_64, armv7h, aarch64. Source builds need Go 1.26+. Tarballs on the releases page →

# three invocations cover everything.

# one file, 16 parallel connections
odm -c 16 https://files.test.xyz/file.tar.gz

# batch: -c = how many files run at once, 1 conn each
odm -c 16 url1 url2 url3 …

# or 4 conns per file → 4 files at a time, rest queue
odm -c 16 -sf 4 url1 url2 url3 …

Large lists go in a file — one URL per line, # comments allowed:

$ odm -i file-list.txt
  1. probe — HEAD → ranged GET → single-stream fallback per URL
  2. plan — the balancer allocates connections (mode A/B/C)
  3. confirm — one prompt with sizes and engines (-y skips)
  4. download — workers pull chunks until the queue drains

# -c is a budget, not a guess.

modewhen-c controlsper file
Aone URLwhole budget → the filemin(-c, 32)
Bmany URLs, no -sffiles in parallel1
Cmany URLs + -sf Nfloor(-c / N) files at onceN + remainder

Servers refusing HTTP range requests get exactly one connection; the freed budget redistributes to the rest in the same pass. Above the soft ceiling of 32 connections per file, odm warns and proceeds. Chunks are handed out from a queue in 4 MiB pieces on demand — one slow peer can't hold the tail hostage, so every worker finishes together.

# four engines. one flag.

odm

Fixed chunks in a work-stealing queue over N real HTTP/1.1 connections. The default — multi-connection aggregation is the point of the tool.

aria2c

Static equal split into --split segments, multiplexed as HTTP/2 streams over one connection. Mirrors aria2c's -s/-x model.

both

A 50/50 split: first half on the odm engine, second half on the aria2c engine — both working the same file at once. Under 4 MiB degrades to plain odm.

smart

Probes range support, size, h2 readiness, then picks per file: small or non-rangeable → odm; ≥ 256 MiB with ≥ 6 conns → both; else → aria2c.

HTTP/2 negotiation needs HTTPS (ALPN). On plain http:// or h1-only servers the h2 profiles fall back automatically.

# aria2c-style: 5 segments over h2
$ odm --profile aria2c -c 5 big.iso

# tune the split
$ odm --profile aria2c --split 4 --min-split-size 10M big.iso

# interrupted is not corrupted.

Each download writes a .odm control file recording finished chunks. Re-run the same command and only the missing ranges are fetched. On resume the stored ETag rides as If-Range: if the remote file changed since the interruption, odm restarts cleanly instead of stitching old bytes to new ones.

Mirrors (--mirror URL, repeatable) join the per-chunk rotation — a throttling source serves fewer chunks while the rest keep speed. Each mirror's responses are validated independently, so a misbehaving one fails its own chunks, not your file. When a server answers 429, the global rate halves so every connection eases off together, then restores your configured cap after a quiet period.

Three ways to verify what landed:

# hash it yourself
$ odm --checksum sha256:<hex> file.iso

# fetch a sha256sum-style sidecar
$ odm --checksum-url file.iso

# Metalink4 embeds the strongest hash
$ odm -i file.meta4

Completed chunks also carry per-chunk SHA-256 digests, verified against disk before any resume continues. A mismatch fails the task — never silent corruption.

# drive it from anywhere.

# start the daemon
$ odm --rpc --rpc-secret hunter2 -d ~/Downloads &

# add a download — token:<secret> first param
$ curl -s -X POST http://127.0.0.1:6900/rpc \
    -H 'Content-Type: application/json' \
    -d '{"jsonrpc":"2.0","method":"odm.addUri",
         "params":["token:hunter2","https://files.test.xyz/x.tar.gz"],"id":1}'

JSON-RPC 2.0 on /rpc, five WebSocket events on /ws (start, progress ≈250 ms, complete, error, pause). Default bind is 127.0.0.1 — pair --rpc-listen-all with --rpc-secret.

odm.addUri / addBatchqueue one or many URLs
odm.pause · unpause · removesteer running tasks (+ *All variants)
odm.tellStatus / Active / Waiting / Stoppedinspect tasks by state
odm.changeOptionrate limits + connections, mid-flight
odm.getGlobalStat · getVersioncounts and capabilities
odm.shutdownwind the daemon down

The event feed carries the same field set as tellStatus, so a GUI needs exactly two endpoints to render live progress. For scripting without RPC, --session-log writes JSONL events to a file.
